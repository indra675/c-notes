C and Embedded C

Interview Cheat Sheet

Read this the night before and again one hour before the interview.

How to answer any question (30 seconds)

1. Say the definition in one line. 2. Give a tiny example. 3. Say why it matters in embedded.

Example: "volatile tells the compiler a value can change outside normal code flow, so it must read it from memory every time. I use it for hardware registers and flags changed in an ISR."

1. Top 30 one-line answers

QuestionAnswer
Pointer?A variable that stores a memory address. & = address of, * = value at.
Dangling pointer?Points to memory that was freed or went out of scope.
Wild pointer?Pointer never initialised, holds a random address.
NULL pointer?Pointer holding 0, points to nothing. Always check before use.
void pointer?Generic pointer without a type. Cast before dereferencing.
const vs #define?const is a typed variable the compiler protects; #define is typeless text replacement.
static (local)?Keeps its value between calls; lives for the whole program.
static (global/function)?Visible only inside that .c file.
extern?Declares a variable defined in another file.
volatile?Value can change outside the code (hardware, ISR). Compiler must not cache it.
const volatile?Read-only for code, changed by hardware (status register).
struct vs union?Struct: members have separate memory. Union: all members share one memory.
Struct padding?Gaps added for alignment. Order members large to small to save RAM.
Stack vs heap?Stack: automatic, fast, for locals. Heap: manual (malloc/free), flexible, can leak.
Memory leak?malloc without free; memory becomes unreachable.
malloc vs calloc?calloc zeroes memory and takes (count, size).
.text .data .bss?Code | initialised globals | zero-initialised globals.
Why globals are 0, locals garbage?Startup code clears .bss; locals sit on the stack with old data.
What runs before main()?Reset handler: set stack, copy .data to RAM, zero .bss, init clock, call main.
Endianness?Byte order of multi-byte values. ESP32, AVR, most ARM are little-endian.
ISR rules?Short, no delay, no printf, no malloc, shared data volatile, set flag and return.
Interrupt latency?Time from the event to the first instruction of the ISR.
Polling vs interrupt?Polling checks repeatedly (simple, wastes CPU); interrupt reacts to events (fast, saves CPU).
Race condition?Result depends on timing between ISR and main using the same data.
Switch bounce?Contacts make/break for 1 to 20 ms. Fix: RC filter or software timing.
Pull-up resistor?Holds an input HIGH when nothing drives it; avoids a floating pin.
PWM?Fast on/off switching; duty cycle sets average power.
Watchdog?Hardware timer that resets the chip if software does not kick it in time.
UART / I2C / SPI?UART: 2 devices, async. I2C: 2 shared wires, addresses. SPI: 4 wires, fast, chip select.
Why avoid malloc in firmware?Fragmentation, unpredictable timing, tiny RAM.

Strings and memory rules

  • String = char array ending with '\0'. "hello" needs 6 bytes. strlen = 5, sizeof = 6.
  • Compare strings with strcmp (0 means equal), never ==.
  • char s[] = "hi" is modifiable. char *s = "hi" points to read-only text.
  • malloc: check for NULL, use n * sizeof *p, free once, set pointer to NULL after free.
  • realloc: assign to a temporary pointer first, otherwise a failure leaks the old block.
  • Macros: put every parameter and the whole expression in brackets. Header files: add include guards.
  • Call by value: functions get copies. Pass a pointer to change the caller's variable.

3. Embedded C quick reference

Bit manipulation

GoalCodeMnemonic
Set bit nx |= (1U << n);SET = OR
Clear bit nx &= ~(1U << n);CLEAR = AND-NOT
Toggle bit nx ^= (1U << n);TOGGLE = XOR
Check bit n(x >> n) & 1CHECK = AND
Read field(x >> pos) & maskshift down, then mask
Write fieldx = (x & ~(mask << pos)) | (val << pos);clear it, then set it

Shift left n = multiply by 2^n. Shift right n = divide by 2^n (unsigned). Use unsigned types and 1U for bit work.

12 & 10 = 8 12 | 10 = 14 12 ^ 10 = 6 ~12 = -13 12 << 1 = 24 12 >> 1 = 6

volatile: needed for 3 things

Mnemonic RIS: Register (hardware) | Interrupt-changed flag | Shared between tasks.

volatile does NOT make access atomic. For multi-byte shared data, disable interrupts briefly.

Memory

SectionHoldsWhere
.textcodeFlash
.rodataconst data, string literalsFlash
.datainitialised globals / staticsFlash copy -> RAM
.bsszero or uninitialised globalsRAM (zeroed at startup)
Heapmalloc, grows upRAM
Stacklocals, return addresses, grows downRAM

Startup order: vector table -> Reset handler -> set stack -> copy .data -> zero .bss -> init clocks -> main().

Little-endian: 0x12345678 stored as 78 56 34 12. Padding: struct {char; int; char} = 12 bytes, reorder to {int; char; char} = 8 bytes.

Stack overflow causes: deep recursion, large local arrays. Fix: make buffers static, avoid recursion, increase task stack.

Interrupts

Flow: event -> flag -> finish instruction -> save context -> vector table -> ISR -> restore -> resume.

ISR mnemonic: SHORT, SIMPLE, no SLEEP (delay), no PRINT. Set a flag, return, do the work in main.

  • Shared variables: volatile. Multi-byte reads on 8-bit chips: noInterrupts() ... interrupts().
  • ESP32 ISRs need IRAM_ATTR. Uno external interrupts only on pins 2 and 3.
  • Clear the interrupt flag if the hardware requires it, or the ISR fires again forever.
  • Debounce button interrupts (ignore triggers within about 50 ms).

GPIO

  • Active-low button: INPUT_PULLUP, pressed = LOW. Input floating = random values.
  • Push-pull drives high and low. Open-drain pulls low only, needs pull-up (I2C).
  • LED resistor: R = (Vsupply - Vled) / I. Example: (3.3 - 2.0) / 0.01 = 130 ohm, use 220 ohm.
  • Motors, relays, solenoids: use a transistor or driver with flyback diode, never a bare GPIO.
  • ESP32 GPIO 34 to 39: input only, no internal pull-ups. ESP32 / ESP8266 pins are 3.3 V only.

7. Code you must be able to write from memory

Bit macros

#define SET_BIT(x, n)     ((x) |=  (1U << (n)))
#define CLEAR_BIT(x, n)   ((x) &= ~(1U << (n)))
#define TOGGLE_BIT(x, n)  ((x) ^=  (1U << (n)))
#define CHECK_BIT(x, n)   (((x) >> (n)) & 1U)

Power of 2, count set bits, swap

int is_pow2(unsigned n) { return n && !(n & (n - 1)); }
 
int count_bits(unsigned n) {
    int c = 0;
    while (n) { n &= n - 1; c++; }      // removes lowest 1 each loop
    return c;
}
 
void swap(int *a, int *b) { int t = *a; *a = *b; *b = t; }
// no temp: a ^= b; b ^= a; a ^= b;

Strings

int my_strlen(const char *s) {
    int n = 0;
    while (*s++) n++;
    return n;
}
 
void reverse(char *s) {
    int i = 0, j = my_strlen(s) - 1;
    while (i < j) { char t = s[i]; s[i++] = s[j]; s[j--] = t; }
}

Endianness check

uint32_t x = 1;
if (*(uint8_t *)&x == 1) puts("little-endian");

Register access and function pointer

#define REG  (*(volatile uint32_t *)0x40020014)   // example address
REG |= (1U << 5);
 
typedef void (*Callback)(void);
Callback cb = my_handler;
cb();

Ring buffer (put and get)

bool rb_put(RB *r, uint8_t b) {
    uint8_t next = (r->head + 1) & (SIZE - 1);
    if (next == r->tail) return false;      // full
    r->buf[r->head] = b;  r->head = next;  return true;
}
bool rb_get(RB *r, uint8_t *b) {
    if (r->head == r->tail) return false;   // empty
    *b = r->buf[r->tail];  r->tail = (r->tail + 1) & (SIZE - 1);  return true;
}

10. Interview day checklist

  • Know your projects cold: purpose, hardware, sensors, protocols, the hardest bug, what you would improve. Practise a 2-minute explanation for each.
  • Say "I don't know, but I would find out by checking the datasheet or testing it" instead of guessing. Honesty plus method impresses.
  • Think aloud when solving a coding question: state the approach, write the code, test with an edge case (0, 1, maximum, empty input).
  • Draw diagrams when asked about memory, interrupts or protocols. Diagrams show understanding.
  • Link answers to your own work: debouncing in your door lock, ADC in your soil sensor, I2C in your OLED projects, interrupts in your traffic signal.
  • Ask one good question at the end: "What does a typical day or first project look like for this role?"
  • Sleep well, carry a pen and paper, and be 15 minutes early.

Last-minute rule

If you remember only 5 things: pointers, bit manipulation, volatile, memory sections and ISR rules. These come up in almost every embedded interview.
