1. What is a data type?

A data type tells the computer three things about a variable:

  1. How much memory to reserve for it (the size).
  2. How to read the bits stored there (as a whole number, a letter, a decimal number...).
  3. Which operations are allowed on it (you can use % on whole numbers, but not on decimals).

Analogy: boxes and labels

Think of memory as a warehouse full of boxes. A data type is the box size plus a label on the box.

int is a medium box labelled "whole numbers only". char is a tiny box labelled "one character". double is a big box labelled "very precise decimal numbers".

Without the label, the same contents can mean different things: the bits 01000001 can be the number 65 or the letter A. The data type decides how they are read.

Why does C need data types?

  • C is a statically typed language: you must declare the type before using a variable.
  • The compiler uses the type to reserve the right amount of memory. Too big wastes RAM, too small loses data. On a microcontroller with 2 KB or 520 KB of RAM, this matters a lot.
  • The compiler uses the type to catch mistakes and to pick the right machine instruction (integer add vs floating-point add).

How you declare a variable

int age;            // declaration: reserves memory, value is garbage
int marks = 85;     // declaration + initialization
float price = 99.5f;
char grade = 'A';

General form: data_type variable_name = value;

3. The int data type in detail

3.1 What is int?

int is short for integer. It stores whole numbers: positive, negative or zero, with no decimal point. Examples: 0, 25, -400, 100000.

Use int for things you count: number of students, loop counters, marks, age, array index.

int students = 60;
int temperature = -5;
int total = students * 2;
 
printf("Students = %d\n", students);   // %d prints an int
scanf("%d", &students);                // %d reads an int (note the &)

Remember

%d is the format specifier for int. Using the wrong one (for example %f for an int) prints garbage.

3.2 How much memory does int use?

The C standard says int must be at least 16 bits (2 bytes). In practice it depends on the processor:

Platformint sizeRange
PC / laptop (Windows, Linux, macOS)4 bytes-2,147,483,648 to 2,147,483,647
ESP32, ESP8266, ARM Cortex-M (STM32)4 bytes-2,147,483,648 to 2,147,483,647
Arduino Uno / Nano (AVR, 8-bit)2 bytes-32,768 to 32,767

Why this matters for you

The same line of code, int x = 40000;, works on your ESP32 but breaks on an Arduino Uno, because 40000 does not fit in 2 bytes.

This is why embedded engineers use fixed-width types like int32_t (see Part 4).

3.3 How the range is calculated

A byte has 8 bits and each bit is 0 or 1. With n bits you can make 2^n different patterns.

  1. 4 bytes = 32 bits, so 2^32 = 4,294,967,296 different values.
  2. Signed int must cover negative and positive numbers, so the values are split roughly in half.
  3. Range of signed n-bit integer: -2^(n-1) to 2^(n-1) - 1.
  4. For 32 bits: -2,147,483,648 to +2,147,483,647 (one more negative value than positive, because zero takes one slot on the positive side).
BitsSigned rangeUnsigned range
8-128 to 1270 to 255
16-32,768 to 32,7670 to 65,535
32-2,147,483,648 to 2,147,483,6470 to 4,294,967,295
64-9,223,372,036,854,775,808 to 9,223,372,036,854,775,8070 to 18,446,744,073,709,551,615

Print the exact limits of your compiler with limits.h:

#include <stdio.h>

int main(void) {
    printf("INT_MIN  = %d\n", INT_MIN);
    printf("INT_MAX  = %d\n", INT_MAX);
    printf("UINT_MAX = %u\n", UINT_MAX);
    return 0;
}

Output:

3.4 int modifiers: short, long, signed, unsigned

Modifiers change the size or the sign of int.

DeclarationTypical sizeFormatNotes
short int (or short)2 bytes%hdSaves memory for small values

long long int8 bytes%lldUse for very large values

  • signed (default): can be negative, positive or zero. Writing int and signed int is the same thing.
  • unsigned: never negative. The extra bit (no sign needed) doubles the positive range.
unsigned int count = 4000000000U;   // fits only in unsigned 32-bit
long long big = 9000000000LL;       // LL suffix = long long
unsigned int u = 10;
 
printf("%u\n", count);
printf("%lld\n", big);

3.5 How int is stored in binary (two's complement)

Computers only store 0s and 1s. A positive int is stored as plain binary. Example with 8 bits for simplicity (a real int uses 32):

DecimalBinary (8-bit)Note
500000101Plain binary: 4 + 1
12701111111Largest signed 8-bit value
-111111111All bits 1 means -1 in two's complement
-511111011See the steps below
-12810000000Smallest signed 8-bit value

How negative numbers are stored (two's complement). To store -5:

  1. Write 5 in binary: 00000101
  2. Invert every bit (0 becomes 1, 1 becomes 0): 11111010
  3. Add 1: 11111011. This is -5.
  • Sign bit: the left-most bit (MSB). 0 means positive, 1 means negative.
  • Why this system? The CPU can use the same adder circuit for positive and negative numbers. 5 + (-5) gives 00000000 (the carry out is thrown away).

See the bits yourself:

#include <stdio.h>
 
void print_bits(unsigned char n) {
    for (int i = 7; i >= 0; i--)
        printf("%d", (n >> i) & 1);
    printf("\n");
}
 
int main(void) {
    print_bits(5);
    print_bits((unsigned char)-5);
    return 0;
}

Output:

00000101
11111011

3.6 Overflow: when the number does not fit

Analogy: the car odometer

A 3-digit odometer shows 999. Drive one more kilometre and it rolls over to 000. A fixed number of bits behaves the same way: after the maximum value it wraps around.

Unsigned overflow is well defined in C: the value wraps around (modulo 2^n).

unsigned char x = 255;
x = x + 1;
printf("%d\n", x);      // 0
 
unsigned char y = 0;
y = y - 1;
printf("%d\n", y);      // 255

Signed overflow is undefined behaviour in C. It often wraps around in practice, but the compiler is allowed to assume it never happens, so your program can behave strangely. Never rely on it.

int a = INT_MAX;
a = a + 1;              // undefined behaviour: do not do this

Real example: factorial overflows quickly with 32-bit int.

  • 12! = 479,001,600 fits in a 32-bit int.
  • 13! = 6,227,020,800 does NOT fit. Use long long (it holds up to 20!) or check before multiplying.

Embedded example

millis() on Arduino returns an unsigned 32-bit counter that wraps to 0 after about 49.7 days. Code that compares times as (now - start) >= interval keeps working across the wrap, because unsigned subtraction also wraps correctly.

3.7 Integer division and the % operator

When both operands are int, the result is an int. The decimal part is thrown away (truncated toward zero).

printf("%d\n", 7 / 2);     // 3   (not 3.5)
printf("%d\n", 7 % 2);     // 1   (remainder)
printf("%d\n", -7 / 2);    // -3  (truncates toward zero)
printf("%d\n", -7 % 2);    // -1  (sign follows the left number)
printf("%f\n", 7 / 2);     // WRONG: int passed to %f
 
printf("%f\n", 7 / 2.0);   // 3.500000  (one operand is double)
printf("%f\n", (float)7 / 2); // 3.500000  (type cast)
  • Dividing by zero (7 / 0 or 7 % 0) crashes the program or gives undefined behaviour. Always check the divisor.
  • % works only with integers. 7.5 % 2 is a compile error.
  • Handy uses of %: check even/odd (n % 2), get the last digit (n % 10), wrap an index (i % size).

3.8 Writing int values (literals and number systems)

Careful

int x = 012; stores 10, not 12. A leading zero makes the number octal. Do not pad numbers with zeros in C source code.

Printing the same value in different systems:

int n = 255;
printf("%d\n", n);    // 255  decimal
printf("%x\n", n);    // ff   hexadecimal
printf("%X\n", n);    // FF
printf("%o\n", n);    // 377  octal

3.9 Mixing int with other types

When you mix types in one expression, C converts them automatically (implicit conversion). Two rules cause most bugs:

  1. Smaller types (char, short) are promoted to int before arithmetic.
  2. If you mix signed and unsigned of the same size, the signed value is converted to unsigned.
int a = -1;
unsigned int b = 1;
 
if (a < b)
    printf("a is smaller\n");
else
    printf("b is smaller\n");   // this prints!

Why? -1 is converted to unsigned, which becomes 4,294,967,295, bigger than 1. This is one of the most common hidden bugs. Avoid comparing signed and unsigned values.

Type casting changes a type on purpose:

int total = 7, count = 2;
float avg = (float)total / count;   // 3.5, cast BEFORE dividing
int x = (int)3.99;                  // 3, decimals are cut, not rounded

Because int can be 2 bytes on one chip and 4 bytes on another, embedded code uses types from stdint.h whose size never changes.

Interview questions with short answers

Q1. What is the size of int in C? It depends on the compiler and the processor. At least 16 bits by the standard; 32 bits on most modern systems (PC, ESP32, ARM), 16 bits on 8-bit AVR (Arduino Uno).

Q2. What is the range of a 32-bit signed int? -2,147,483,648 to 2,147,483,647, which is -2^31 to 2^31 - 1.

Q3. How are negative numbers stored? In two's complement: invert all bits of the positive number and add 1. The left-most bit acts as the sign bit.

Q4. Difference between signed and unsigned int? Signed can hold negative values; unsigned cannot but has twice the positive range.

Q5. What happens on integer overflow? Unsigned wraps around (modulo 2^n). Signed overflow is undefined behaviour.

Q6. What is the result of 7 / 2 in C? 3, because both operands are int and the decimal part is truncated.

Q7. What is the result of -7 % 2? -1. The sign of the remainder follows the left operand (since C99).

Q8. Why use uint8_t instead of unsigned char or int in embedded code? Its size is guaranteed (exactly 8 bits), so the code behaves the same on every chip, and it clearly shows the data is a raw byte.

Q9. What does this print: int a = -1; unsigned int b = 1; printf("%d", a < b); 0, because a is converted to unsigned (4,294,967,295) and the comparison is false.

Q10. What is the difference between int x = 012 and int x = 12? 012 is octal and equals 10; 12 is decimal and equals 12.

6. Quick look at the other basic types

Each of these deserves its own detailed chapter. Here is the short version so the overview is complete.

char

  • Size: 1 byte. Stores one character such as 'A', or a small number.
  • A character is stored as its ASCII number: 'A' is 65, 'a' is 97, '0' is 48.
  • Use %c to print as a letter and %d to print the number.
  • Whether plain char is signed or unsigned depends on the compiler, so use uint8_t for raw bytes.
char ch = 'A';
printf("%c %d\n", ch, ch);    // A 65
printf("%c\n", ch + 1);        // B

float and double

  • Store numbers with a decimal point. They are stored in binary scientific form (IEEE 754), so many decimals are only approximate.
  • float: 4 bytes, about 6 to 7 correct digits. double: 8 bytes, about 15 to 16 correct digits.
  • Never compare two floats with ==. Compare the difference with a small tolerance instead.
  • Many small microcontrollers have no floating-point hardware, so float maths is slow there. Prefer integers when you can (for example, store 25.5 degrees as 255 tenths).
float a = 0.1f + 0.2f;
printf("%.10f\n", a);   // 0.3000000119 (not exactly 0.3)

void

  • Means "no value". Used for functions that return nothing (void blink(void)) and for generic pointers (void *).
  • You cannot create a variable of type void.
