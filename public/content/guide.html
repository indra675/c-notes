TOPIC 1

Basics and Data Types

In one line

A C program is translated by the compiler into machine code; every variable has a data type that decides its size, how its bits are read and what you can do with it.

1.1 How a C program becomes a running program

You write text (source code). The computer only understands machine code. Four tools turn one into the other, like a factory line.

StageToolWhat it does
1. PreprocessPreprocessorHandles lines starting with # (include files, replace macros)
2. CompileCompilerTurns C into assembly and checks syntax
3. AssembleAssemblerTurns assembly into an object file (machine code pieces)
4. LinkLinkerJoins object files and libraries into one executable
// hello.c
#include <stdio.h>
 
int main(void) {
    printf("Hello, embedded world!\n");
    return 0;
}

Output:

Hello, embedded world!

Compile and run on a PC: gcc hello.c -o hello then ./hello

  • #include <stdio.h> pastes the declarations of printf and scanf into your file.
  • main is where every C program starts. return 0 tells the operating system "success".
  • Every statement ends with a semicolon. Blocks use curly braces { }.
  • On a microcontroller the same stages happen, but the result is flashed into the chip instead of run on the PC.

1.2 Variables and constants

A variable is a named box in memory. You choose the name, the compiler chooses the address.

  • Names can use letters, digits and underscore, and cannot start with a digit. count1 is fine, 1count is not.
  • C is case sensitive: Total and total are different variables.
  • You cannot use keywords (int, return, while...) as names.
  • Use meaningful names: temperature_c is better than t.
int age = 20;                 // variable: value can change
const float PI = 3.14159f;    // constant: compiler blocks changes
#define MAX_USERS 50          // macro: text replaced before compiling
 
age = 21;       // fine
// PI = 3.14;   // ERROR: assignment of read-only variable

1.3 What is a data type?

A data type tells the compiler (1) how much memory to reserve, (2) how to read the bits stored there, and (3) which operations are allowed.

Analogy: boxes with labels

Memory is a warehouse of boxes. The type is the box size plus a label. The bits 01000001 mean the number 65 if the label says int, and the letter A if the label says char.

Important for embedded

The size of int is not fixed. It is 2 bytes on an Arduino Uno and 4 bytes on ESP32, ESP8266 and STM32. Embedded code uses uint8_t, uint16_t, uint32_t (see Topic 11).

1.4 int in short

  • Stores whole numbers. A signed 32-bit int covers -2,147,483,648 to 2,147,483,647.
  • Negative numbers are stored in two's complement: invert the bits of the positive number and add 1.
  • Unsigned overflow wraps around (255 + 1 becomes 0 in 8 bits). Signed overflow is undefined behaviour.
  • 7 / 2 is 3 (decimals are dropped) and 7 % 2 is 1 (remainder).
  • The full int chapter is in the separate document "Data Types in C with int Explained".

1.5 char, float and double

  • char stores a character as its ASCII number: 'A' = 65, 'a' = 97, '0' = 48. So 'A' + 1 is 66 which prints as B.
  • float and double store numbers in binary scientific form (IEEE 754), so many decimals are approximate. 0.1 cannot be stored exactly.
  • Do not compare floats with ==. Compare the difference with a small tolerance.
  • Many small microcontrollers have no floating-point hardware, so float maths is slow. Use integers when you can (store 25.5 degrees as 255 tenths).
char  ch = 'A';
float f  = 0.1f + 0.2f;
 
printf("%c %d\n", ch, ch);      // A 65
printf("%c\n", ch + 1);          // B
printf("%.10f\n", f);            // 0.3000000119 (not exactly 0.3)
printf("%zu\n", sizeof(double)); // 8

Interview questions with short answers

Q1. What is a data type? It defines the size, interpretation and allowed operations of a variable.

Q2. What are the stages of compilation? Preprocessing, compiling, assembling, linking.

Q3. Difference between const and #define? const creates a typed variable that the compiler protects; #define is plain text replacement before compiling and has no type.

Q4. Why is sizeof(int) not always 4? The standard only sets a minimum (16 bits); the real size depends on the processor and compiler.

Q5. What does void main() vs int main() mean? The standard form is int main(void), returning a status to the OS. void main is non-standard on hosted systems, though common in bare-metal code.

Operators and Control Flow

In one line

Operators calculate and compare values; control flow (if, switch, loops) decides which code runs and how many times.

2.2 Pre-increment vs post-increment

int a = 5, b;
b = a++;   // use a first (b = 5), then add 1 (a = 6)
printf("%d %d\n", a, b);
 
a = 5;
b = ++a;   // add 1 first (a = 6), then use it (b = 6)
printf("%d %d\n", a, b);

Output:

6 5
6 6

2.3 Short-circuit evaluation

With && and ||, C stops as soon as the answer is known. In (a != 0 && 10 / a > 2), if a is 0 the division is never evaluated, so there is no crash. Use this deliberately to guard risky checks.

The classic bug: = versus ==

if (x = 5) assigns 5 to x and is always true. You wanted if (x == 5). A habit that helps: write if (5 == x) so a typo becomes a compile error.

2.4 Operator precedence (high to low)

  1. Brackets ( ), array [ ], member . and ->
  2. Unary: ! ~ ++ -- * (dereference) & (address) sizeof
  3. * / % then + -
  4. << >> then < <= > >= then == !=
  5. & then ^ then | then && then ||
  6. ?: then = and compound assignments

When in doubt, use brackets. They cost nothing and remove the guesswork.

2.5 Decision making: if, else if, else

int marks = 72;
 
if (marks >= 90)       printf("Grade A\n");
else if (marks >= 75)  printf("Grade B\n");
else if (marks >= 60)  printf("Grade C\n");
else                   printf("Fail\n");
 
int max = (a > b) ? a : b;     // ternary

Output:

Grade C

2.6 switch

Use switch when one integer or char variable is compared with many fixed values. break ends the case; without it, execution falls through into the next case.

char op = '*';
int a = 6, b = 3;
 
switch (op) {
    case '+': printf("%d\n", a + b); break;
    case '-': printf("%d\n", a - b); break;
    case '*': printf("%d\n", a * b); break;
    case '/': printf("%d\n", a / b); break;
    default:  printf("Unknown operator\n");
}

Output:

18

Interview questions with short answers

Q1. Difference between ++a and a++? Pre-increment adds 1 then uses the value; post-increment uses the value then adds 1.

Q2. Difference between while and do-while? do-while checks the condition after the body, so it always runs at least once.

Q3. What is short-circuit evaluation? In a && b, b is skipped if a is false; in a || b, b is skipped if a is true.

Q4. What happens if you forget break in switch? Execution falls through into the next case.

Q5. Why do embedded programs use while(1)? There is no OS to return to, so main loops forever handling tasks.

TOPIC 3

Functions and Recursion

In one line

A function is a named block of code you write once and call many times; recursion is a function that calls itself to solve a smaller version of the same problem.

3.1 Why functions?

  • Reuse: write once, call anywhere.
  • Readability: main() reads like a story (read_sensor(), update_display()).
  • Testing: test small pieces separately.
  • Teamwork: each engineer writes different functions (drivers).

Analogy: a recipe card

The function is the recipe. The parameters are the ingredients you hand over. The return value is the dish you get back. Calling the function is cooking from that card.

3.2 Anatomy of a function

#include <stdio.h>
 
int add(int a, int b);          // prototype (declaration)
 
int main(void) {
    int result = add(3, 4);     // call
    printf("%d\n", result);
    return 0;
}
 
int add(int a, int b) {         // definition
    return a + b;
}

Output:

7

3.3 Call by value

C passes copies of the arguments. Changing the parameter inside the function does not change the original variable.

void bad_swap(int a, int b) {
    int t = a;  a = b;  b = t;     // swaps only the copies
}
 
int x = 1, y = 2;
bad_swap(x, y);
printf("%d %d\n", x, y);           // still 1 2

Output:

1 2

To change the original you pass its address (a pointer). That is the swap fix in Topic 5.

3.4 Scope and lifetime

Prefer local variables. Too many globals make code hard to debug, because any function can change them. In embedded code, globals shared with an ISR must be volatile (Topic 11).

3.5 Recursion

A recursive function must have (1) a base case that stops the recursion and (2) a recursive case that moves toward the base case.

unsigned long factorial(unsigned int n) {
    if (n <= 1)                    // base case
        return 1;
    return n * factorial(n - 1);   // recursive case
}

3.6 What happens in memory: the stack

Every call pushes a stack frame (parameters, local variables, return address). When the function returns, the frame is removed. Deep recursion means many frames; run out of stack and the program crashes (stack overflow).

Recursion on microcontrollers

An ESP8266 or Uno has very little RAM and stack. Many embedded coding standards (MISRA) forbid recursion. Prefer loops in firmware; use recursion to learn and in tree or parsing problems on PCs.

int fib(int n) {                 // easy to read, but slow: it repeats work
    if (n < 2) return n;
    return fib(n - 1) + fib(n - 2);
}
 
int fib_loop(int n) {            // fast and uses constant stack
    int a = 0, b = 1;
    for (int i = 0; i < n; i++) { int t = a + b; a = b; b = t; }
    return a;
}

Interview questions with short answers

Q1. What is call by value? The function receives copies of the arguments, so changes do not affect the originals.

Q2. Difference between declaration and definition? A declaration tells the compiler the signature; the definition provides the body.

Q3. What is a stack frame? The block of stack memory holding a call's parameters, locals and return address.

Q4. What is the base case in recursion? The condition where the function stops calling itself.

Q5. Why avoid recursion in firmware? Stack is small and usage is hard to predict; overflow causes a crash that is hard to debug.

Q6. What does static do to a local variable? It keeps its value between calls and lives for the whole program.

TOPIC 4

Arrays and Strings

In one line

An array is a row of same-type variables stored side by side in memory; a string in C is simply a char array that ends with the null character '\0'.

4.1 One-dimensional arrays

Analogy: a row of lockers

Lockers are numbered 0, 1, 2... All lockers are the same size and sit next to each other. The array name is the building; the index picks the locker.

int marks[5] = {90, 85, 70, 60, 95};     // 5 ints, 20 bytes on a 32-bit int system
int zeros[5] = {0};                      // all zeros
int auto_size[] = {1, 2, 3};             // compiler counts: size 3
 
printf("%d\n", marks[0]);                // 90  (first element)
printf("%d\n", marks[4]);                // 95  (last element)
 
for (int i = 0; i < 5; i++)
    printf("%d ", marks[i]);
 
int n = sizeof(marks) / sizeof(marks[0]);   // number of elements = 5
  • Indexes run from 0 to size-1. An array of 5 has marks[0] to marks[4].
  • Elements sit in consecutive memory: address of marks[1] = address of marks[0] + sizeof(int).
  • C does not check bounds. marks[10] compiles and corrupts other memory or crashes: undefined behaviour.
  • Without an initialiser, a local array holds garbage values.

4.2 Two-dimensional arrays

int m[2][3] = { {1, 2, 3},
                {4, 5, 6} };            // 2 rows, 3 columns
 
for (int r = 0; r < 2; r++) {
    for (int c = 0; c < 3; c++)
        printf("%d ", m[r][c]);
    printf("\n");
}

Output:

1 2 3 
4 5 6

Memory is one long line; C stores rows one after another (row-major). So m[1][0] sits right after m[0][2].

4.3 Passing arrays to functions

An array passed to a function becomes a pointer to its first element, so the function can change the original. The size is lost, so pass it separately.

void print_array(const int arr[], int n) {      // const: we only read it
    for (int i = 0; i < n; i++)
        printf("%d ", arr[i]);
}
 
int find_max(const int arr[], int n) {
    int max = arr[0];
    for (int i = 1; i < n; i++)
        if (arr[i] > max) max = arr[i];
    return max;
}

4.4 Searching and sorting

// Bubble sort: repeatedly swap neighbours that are out of order
void bubble_sort(int a[], int n) {
    for (int i = 0; i < n - 1; i++)
        for (int j = 0; j < n - 1 - i; j++)
            if (a[j] > a[j + 1]) {
                int t = a[j];  a[j] = a[j + 1];  a[j + 1] = t;
            }
}

After pass 1 the largest element has "bubbled" to the end; after pass 2 the second largest is in place, and so on. Fine for learning; real code uses qsort or better algorithms.

4.5 Strings

C has no string type. A string is a char array whose last element is '\0' (the null terminator, value 0). Functions find the end of the string by looking for it.

char s1[] = "hello";               // size 6: h e l l o \0
char s2[10] = "hi";                // h i \0 and 7 more zeros
char s3[] = {'o', 'k', '\0'};      // same idea, written by hand
 
printf("%s\n", s1);                // hello
printf("%zu\n", sizeof(s1));       // 6  (array size)
printf("%zu\n", strlen(s1));       // 5  (characters before \0)
Function (string.h)What it does

Never compare strings with ==

if (a == b) compares addresses, not text. Use strcmp(a, b) == 0.

4.6 Reading strings safely

char name[20];
 
scanf("%19s", name);          // reads one word, max 19 chars (leaves room for \0)
 
fgets(name, sizeof(name), stdin);    // reads a whole line including spaces
name[strcspn(name, "\n")] = '\0';    // remove the newline fgets keeps

4.7 Writing your own strlen and reverse

int my_strlen(const char *s) {
    int n = 0;
    while (s[n] != '\0') n++;
    return n;
}
 
void reverse(char s[]) {
    int i = 0, j = my_strlen(s) - 1;
    while (i < j) {
        char t = s[i];  s[i] = s[j];  s[j] = t;
        i++;  j--;
    }
}

Embedded note: serial commands, sensor names and display text are all strings. Always size buffers carefully: a UART buffer overflow can crash the device or corrupt memory.

Interview questions with short answers

Q1. Why do arrays start at index 0? The index is an offset from the first element: address = base + index x size.

Q2. What is the null terminator? The character '\0' (value 0) that marks the end of a C string.

Q3. sizeof("hello") vs strlen("hello")? sizeof is 6 (includes \0); strlen is 5.

Q4. Does C check array bounds? No. Out-of-range access is undefined behaviour.

Q5. Difference between char s[] = "hi" and char *s = "hi"? The first is a modifiable array copy; the second points to a read-only literal.

Q6. How is a 2D array stored in memory? Row by row, in one contiguous block (row-major order).

TOPIC 5

Pointers

In one line

A pointer is a variable that stores the memory address of another variable. Pointers let functions change the caller's data, walk through arrays, and talk directly to hardware.

5.1 The idea

Analogy: house and address

A variable is a house. Its value is the person living inside. The address is the house number written on a paper slip. A pointer is the slip of paper: it is not the house, it only tells you where the house is.

SymbolMeaning
&xAddress of x ("where does x live?")
int *pDeclare p as a pointer to an int
*pDereference: go to the address stored in p and use the value there
NULLA pointer that points to nothing (address 0)
int x = 10;
int *p = &x;          // p holds the address of x
 
printf("%d\n", x);    // 10
printf("%p\n", (void *)p);   // address, for example 0x7ffd5c3a

5.2 Pointer size

A pointer holds an address, so its size depends on the machine, not on what it points to: 8 bytes on 64-bit PCs, 4 bytes on ESP32, ESP8266 and ARM Cortex-M, 2 bytes on 8-bit AVR (Arduino Uno).

5.3 Call by reference: the swap that works

void swap(int *a, int *b) {
    int t = *a;
    *a = *b;
    *b = t;
}
 
int x = 1, y = 2;
swap(&x, &y);
printf("%d %d\n", x, y);    // 2 1

Output:

2 1

C still passes by value, but the value passed is an address, so the function can reach the original. Functions that must return more than one result also use pointers (output parameters).

5.4 Pointer arithmetic

Adding 1 to a pointer moves it by one element, not one byte. For int *p, p + 1 adds sizeof(int) to the address.

int arr[4] = {10, 20, 30, 40};
int *p = arr;                 // array name = address of first element
 
printf("%d\n", *p);           // 10
printf("%d\n", *(p + 2));     // 30
p++;                          // now points to arr[1]
printf("%d\n", *p);           // 20
 
// arr[i] is exactly the same as *(arr + i)
  • Allowed: pointer + integer, pointer - integer, pointer - pointer (same array), comparing pointers.
  • Not allowed: adding two pointers, multiplying pointers.
  • An array name is not a variable: you cannot write arr++ (but p++ is fine).

5.5 Arrays, strings and pointers

char *s = "embedded";           // points to a read-only literal
int count = 0;
while (*s != '\0') {            // walk until the terminator
    count++;
    s++;
}
printf("%d\n", count);          // 8

5.6 Pointer to pointer, void pointer, NULL

  • int **pp = &p; : pp points to p, which points to an int. **pp is the int. Used for 2D data and to let a function change a pointer.
  • void *: a pointer with no type. It can hold any address but must be cast before use. malloc returns void *.
  • NULL: always check a pointer against NULL before using it: if (p != NULL) { ... }.

5.8 Function pointers

A function also lives at an address. A function pointer stores it, so you can choose which function to call at run time (callbacks, state machines, driver tables).

printf("%d\n", op(5, 3));     // 8
op = sub;
printf("%d\n", op(5, 3));     // 2

Structures, Unions, Enums and typedef

In one line

A struct groups different variables under one name, a union lets members share the same memory, an enum gives names to integer constants, and typedef gives a type a shorter name.

6.1 Structures

Analogy: a form

An array is a stack of identical sheets. A struct is one form with different fields: name, roll number, marks. One form describes one student.

struct Student {
    char  name[20];
    int   roll;
    float marks;
};
 
struct Student s1 = {"Ravi", 101, 88.5f};
struct Student s2;
 
s2.roll = 102;                       // . accesses a member
strcpy(s2.name, "Anu");
s2.marks = 91.0f;
 
printf("%s %d %.1f\n", s1.name, s1.roll, s1.marks);

Output:

Ravi 101 88.5

6.2 Pointers to structures and the arrow operator

Structures can be large. Passing a pointer avoids copying the whole struct, and the function can modify the original. Use -> with a pointer, . with a variable.

void print_student(const struct Student *s) {
    printf("%s %d %.1f\n", s->name, s->roll, s->marks);   // same as (*s).name
}
 
void give_bonus(struct Student *s) {
    s->marks += 5;
}
 
print_student(&s1);
give_bonus(&s1);

typedef struct {
    float temperature;
    float humidity;
    uint32_t timestamp;
} SensorData;
 
SensorData reading = {27.5f, 60.0f, 1000};   // no need to write "struct"

typedef does not create a new type; it just gives a new name. It is used everywhere in embedded code: uint8_t itself is a typedef.

6.5 Struct padding and size

CPUs read memory fastest when a 4-byte int starts at an address divisible by 4. The compiler inserts unused padding bytes to keep members aligned, so sizeof(struct) can be bigger than the sum of its members.

struct A { char a; int b; char c; };   // a, 3 pad, b (4), c, 3 pad  -> 12 bytes
struct B { int b; char a; char c; };   // b (4), a, c, 2 pad          ->  8 bytes
 
printf("%zu %zu\n", sizeof(struct A), sizeof(struct B));   // 12 8

Output:

12 8

Tip: list members from largest to smallest to save RAM. This matters when you have thousands of records on a microcontroller.

6.6 Unions

In a union all members start at the same address. The size is that of the largest member, and only one member holds a meaningful value at a time.

union Data {
    int   i;
    float f;
    uint8_t bytes[4];
};
 
union Data d;
d.f = 1.0f;
printf("%02X %02X %02X %02X\n", d.bytes[0], d.bytes[1], d.bytes[2], d.bytes[3]);
printf("%zu\n", sizeof(union Data));

Output:

00 00 80 3F
4

The output shows the four bytes of the float 1.0 (0x3F800000) on a little-endian machine, lowest byte first. Embedded uses of unions: viewing a 32-bit register as bytes or as bit fields, and sending different message types in one buffer.

6.7 Enumerations

An enum gives readable names to integer constants. Values start at 0 and increase by 1 unless you set them.

enum Color { RED, GREEN, BLUE };            // 0, 1, 2

Use enums for states in a state machine (Topic 18) instead of magic numbers like 0, 1, 2.

6.8 Bit-fields

struct Flags {

    unsigned int mode    : 2;    // 2 bits (0 to 3)
    unsigned int error   : 1;
    unsigned int         : 4;    // 4 unused bits
};
 
struct Flags f = {0};
f.power = 1;
f.mode  = 2;

Bit-fields are not portable

The order of bits and the packing are decided by the compiler. For hardware registers and communication protocols, most engineers use masks and shifts (Topic 10) instead.

In one line

Dynamic memory lets a program request memory from the heap while it runs (malloc) and must give it back (free). On small microcontrollers it is usually avoided.

7.1 Stack vs heap

Analogy: hotel rooms

Stack is your own room that is cleaned automatically when you leave. Heap is renting a hall: you ask the manager (malloc), use it as long as you like, and must hand the keys back (free). If you forget, nobody else can use that hall.

7.2 The four functions (stdlib.h)

FunctionWhat it does
malloc(size)Reserves size bytes; memory is NOT cleared; returns NULL on failure
calloc(n, size)Reserves n x size bytes and sets all to zero
realloc(ptr, size)Resizes a block (may move it); returns the new address
free(ptr)Returns the block to the heap
#include <stdio.h>
#include <stdlib.h>
 
int main(void) {
    int n = 5;
    int *arr = malloc(n * sizeof *arr);     // space for 5 ints
    if (arr == NULL) {                      // ALWAYS check
        printf("Out of memory\n");
        return 1;
    }
 
    for (int i = 0; i < n; i++) arr[i] = i * i;
 
    // grow to 10 elements: use a temporary pointer
    int *tmp = realloc(arr, 10 * sizeof *arr);
    if (tmp == NULL) { free(arr); return 1; }
    arr = tmp;
 
    for (int i = 5; i < 10; i++) arr[i] = i * i;
    for (int i = 0; i < 10; i++) printf("%d ", arr[i]);
 
    free(arr);          // give it back
    arr = NULL;         // avoid a dangling pointer
    return 0;
}

Output:

0 1 4 9 16 25 36 49 64 81

Why sizeof *arr? It stays correct even if you change the pointer type later. Why a temporary pointer in realloc? If realloc fails it returns NULL, and writing that straight into arr would lose the old block (a leak).

7.4 Linked list: a classic heap use

An array has a fixed size. A linked list grows one node at a time; each node holds data and a pointer to the next node.

typedef struct Node {
    int data;
    struct Node *next;
} Node;
 
Node *push_front(Node *head, int value) {
    Node *n = malloc(sizeof *n);
    if (n == NULL) return head;
    n->data = value;
    n->next = head;          // new node points to old first node
    return n;                // new node is now the head
}
 
void print_list(const Node *head) {
    for (const Node *p = head; p != NULL; p = p->next)
        printf("%d -> ", p->data);
    printf("NULL\n");
}
 
void free_list(Node *head) {
    while (head != NULL) {
        Node *next = head->next;     // save before freeing
        free(head);
        head = next;
    }
}
 
int main(void) {
    Node *list = NULL;
    list = push_front(list, 3);
    list = push_front(list, 2);
    list = push_front(list, 1);
    print_list(list);
    free_list(list);
    return 0;
}

Output:

1 -> 2 -> 3 -> NULL

7.5 Dynamic memory in embedded systems

  • Small chips have kilobytes of RAM. Repeated malloc and free cause fragmentation: enough total free memory but no single block big enough.
  • Allocation time is unpredictable, which hurts real-time behaviour.
  • Safety-critical standards (MISRA, automotive, medical) often forbid heap use after start-up.
  • Preferred: static arrays, fixed-size buffers and memory pools.
  • On ESP32 you do have a heap and FreeRTOS; allocate once at start-up and keep it. Check free heap with ESP.getFreeHeap() in Arduino code.

auto is the default for local variables, so you almost never type it. register is a request to the compiler that modern compilers ignore (they decide better).

8.2 static

static does two different jobs depending on where it is written.

  • static inside a function: the variable keeps its value between calls (lifetime = whole program) but only that function can see it.
  • static at file level (global or function): it is private to this .c file (internal linkage). Other files cannot access it.
void counter(void) {
    static int count = 0;      // initialised once only
    count++;
    printf("called %d times\n", count);
}
 
counter();   // called 1 times
counter();   // called 2 times
counter();   // called 3 times

Embedded use

Use static for file-private variables and helper functions in a driver. It works like "private" in other languages and prevents name clashes between files.

8.3 extern

extern says "this variable exists, it is defined in another file". It declares without creating.

// config.c
int baud_rate = 115200;          // definition: memory is created here
 
// main.c
#include <stdio.h>
extern int baud_rate;            // declaration: refers to the one above
 
int main(void) { printf("%d\n", baud_rate); return 0; }

Normally you put the extern declaration in a header file (config.h) so every file shares the same one.

8.4 The preprocessor

File Handling

In one line

File handling lets a program store data permanently by reading and writing files using a FILE pointer and functions such as fopen, fprintf, fread and fclose.

9.1 Why files?

Variables vanish when the program ends. Files keep data: logs, configuration, records. On microcontrollers the same ideas apply to an SD card, SPIFFS or LittleFS on ESP32 (the function names differ slightly but the steps are the same).

Analogy: a notebook

Open the notebook (fopen), read or write on it (fprintf, fscanf, fread, fwrite), and close it (fclose) so everything is saved.

9.2 Steps for every file operation

  2. Open the file with fopen and check it did not return NULL.
  3. Read or write.
  4. Close with fclose.

        return 1;

Bitwise Operators and Bit Manipulation

In one line

Bitwise operators work on the individual bits of a number. They are the main tool for controlling hardware registers, flags and protocols in embedded C.

10.1 Why bits matter in embedded

A hardware register is a number where each bit (or group of bits) controls one thing: bit 5 turns an LED pin on, bits 2 to 4 select a clock speed, bit 7 says "data ready". To change one bit without disturbing the others, you need bitwise operators.

Analogy: a row of light switches

A byte is a panel of 8 switches. Bitwise operators let you flip one switch, check one switch, or set a pattern, without touching the others.

10.4 Multi-bit fields: mask, shift, insert

Suppose bits 4 to 6 of a register hold a 3-bit "mode" value.

#define MODE_SHIFT 4
#define MODE_MASK  (0x7U << MODE_SHIFT)       // 0111 0000
 
uint8_t reg = 0xA5;                           // 1010 0101
 
// READ the field: shift it down, then mask
uint8_t mode = (reg >> MODE_SHIFT) & 0x7U;    // 010 = 2
 
// WRITE the field: clear the old bits, then OR in the new value
reg = (reg & ~MODE_MASK) | ((5U << MODE_SHIFT) & MODE_MASK);   // mode = 101

This "clear then set" pattern is the standard way to update part of a register safely.

10.5 Classic tricks (frequent interview questions)

// even or odd
if (n & 1) { /* odd */ }
 
// power of two (n must be > 0)
int is_pow2 = (n > 0) && ((n & (n - 1)) == 0);
 
// count set bits (Kernighan): each loop removes the lowest 1 bit
int count_bits(unsigned int n) {
    int c = 0;
    while (n) { n &= (n - 1); c++; }
    return c;
}
 
// swap two numbers without a temporary variable
a ^= b;  b ^= a;  a ^= b;
 
// swap the two nibbles of a byte
uint8_t swapped = (uint8_t)((x << 4) | (x >> 4));
 
// multiply and divide by 8 (unsigned)
y = x << 3;     // x * 8
z = x >> 3;     // x / 8

Why n & (n-1) works: subtracting 1 flips the lowest 1 bit to 0 and all the zeros below it to 1, so AND-ing removes exactly that lowest 1.

10.6 Traps to remember

  • Precedence: == binds tighter than &. Write if ((x & 4) == 4), not if (x & 4 == 4).
  • Use unsigned types (or 1U, 1UL) for shifts. Shifting a signed negative value is implementation-defined, and shifting 1 into the sign bit of an int is undefined.
  • Do not shift by the width of the type or more (1 << 32 on a 32-bit int is undefined).
  • On 8-bit and 16-bit systems use 1UL << n if n can be 16 or more, otherwise the 1 is only 16 bits wide.
  • Integer promotion: uint8_t values become int in expressions, so ~x on a uint8_t gives a 32-bit result. Cast back: (uint8_t)~x.

10.7 Real hardware example (Arduino Uno, AVR)

// Pin 13 on the Uno is PB5. Blink it with direct register access.

}
 
void loop() {
    PORTB ^= (1 << PORTB5);       // toggle only PB5, other pins untouched
    delay(500);
}

DDRB is the direction register (1 = output). PORTB holds the output levels. One line toggles one pin and leaves the other seven alone. This is exactly why you learn bit manipulation.

Type Qualifiers and Fixed-Width Types

In one line

volatile, const and static tell the compiler extra facts about a variable; fixed-width types (uint8_t, uint32_t...) make sizes identical on every chip.

11.1 volatile

Compilers optimise. If your code reads a variable in a loop and nothing in that loop changes it, the compiler assumes it never changes and reads it only once. That is wrong if hardware or an interrupt changes it behind the compiler's back. volatile means: "this value can change at any time, always read it from memory and never cache it."

Analogy: a whiteboard in a busy office

Without volatile, the compiler copies the whiteboard into its notebook once and keeps reading its notes. With volatile, it must look at the whiteboard every single time, because someone else keeps writing on it.

int flag = 0;                      // BUG: not volatile
 
void ISR(void) { flag = 1; }       // interrupt sets the flag
 
int main(void) {
    while (flag == 0) { }          // compiler may turn this into an endless loop
    do_work();
}
 
// FIX
volatile int flag = 0;

Three situations that need volatile:

SituationExample
Hardware registervolatile uint32_t *status = (volatile uint32_t *)0x40021018;
Variable changed in an ISR and read in main (or the reverse)volatile uint8_t button_pressed;
Variable shared between tasks / threads (with proper locking)volatile bool running;

volatile does not make code safe

volatile only stops the compiler from caching the value. It does not make a multi-byte read atomic. On an 8-bit AVR, reading a 16-bit volatile variable takes two instructions; an interrupt in between can give a half-old, half-new value. Disable interrupts around such reads (Topic 15).

11.2 const

  • const means the program may not modify the value. The compiler reports an error if you try.
  • It documents intent: a function taking const char *s promises not to change the string.
  • Global const data is placed in flash (read-only memory) on most microcontrollers, saving RAM. On AVR Arduino you need PROGMEM to be sure; on ESP32 and ARM it happens automatically.
const int MAX_RETRY = 3;                       // cannot change
const uint8_t sine_table[8] = {0, 90, 127, 90, 0, 90, 127, 90};   // lookup table in flash
 
int length(const char *s);                     // promises not to modify s

11.3 const volatile together

This looks contradictory but is common for read-only hardware registers, for example a status register or an input-port register. Your code must not write it (const), but the hardware changes it all the time (volatile).

const volatile uint32_t *const STATUS_REG = (const volatile uint32_t *)0x40010000;
 
while ((*STATUS_REG & 0x01) == 0) { }   // wait until the ready bit is set

12.3 What happens before main() runs

The CPU does not start at main. After power-on or reset it runs startup code:

  1. The CPU reads the vector table at a fixed address: the first entry is the initial stack pointer, the second is the address of the Reset handler.
  2. Reset_Handler starts. It sets up the stack pointer.
  3. It copies the initial values of .data from flash to RAM.
  4. It fills .bss with zeros. (This is why uninitialised globals are 0.)
  5. It sets up the clock and basic hardware (SystemInit on ARM).
  6. It calls main().

The linker script (.ld file) decides the addresses of flash and RAM and where each section goes. You rarely write it as a beginner, but you should know it exists. In Arduino and ESP-IDF these steps are hidden inside the core.

Why interviewers ask this

It shows you understand why a global initialised to 5 survives reset, why uninitialised globals are zero, and why local variables contain garbage.

12.4 Stack overflow

  • Each function call and each local array uses stack. Large local arrays (char buf[2000]) or deep recursion can exhaust a small stack.
  • The stack then overwrites other data, causing random crashes that are very hard to debug.
  • Fixes: make big buffers global or static, avoid recursion, check stack usage (FreeRTOS: uxTaskGetStackHighWaterMark), increase task stack size.

12.5 Structure padding (recap with detail)

Processors prefer a 4-byte value at an address divisible by 4. The compiler adds padding to guarantee alignment.

struct A { char a; int b; char c; };   // offsets: a=0, b=4, c=8, size 12
struct B { int b; char a; char c; };   // offsets: b=0, a=4, c=5, size 8
 
// remove padding (slower access, not portable, may fault on some CPUs)
struct __attribute__((packed)) P { char a; int b; char c; };   // size 6

Packed structs are useful for matching a communication packet byte by byte, but unaligned access can be slow or even cause a hardware fault on some ARM cores. Prefer ordering members largest first.

Registers, Memory-Mapped I/O and Function Pointers

In one line

In a microcontroller, peripherals (GPIO, timers, UART) are controlled by writing numbers to special memory addresses called registers; C does this with volatile pointers to fixed addresses.

13.1 What is a register?

A register is a small memory location, 8, 16 or 32 bits wide, that is connected to hardware instead of ordinary RAM. Writing to it changes hardware behaviour; reading it tells you the hardware state.

Analogy: the control panel of a machine

Every switch and gauge on the panel has a fixed position. Memory-mapped I/O means each switch and gauge has a fixed memory address. Writing to the address flips the switch; reading the address reads the gauge.

Register typePurpose

DataHold the data to send or the data received
Direction (GPIO)Choose input or output per pin

13.2 Accessing a fixed address

The pattern is: cast the address to a pointer to volatile, then dereference.

// NOTE: 0x40020014 is an example address. Real addresses come from
// the chip's reference manual or its header file.
#define GPIOA_ODR   (*(volatile uint32_t *)0x40020014)
 
GPIOA_ODR |=  (1U << 5);     // set pin 5 high
GPIOA_ODR &= ~(1U << 5);     // set pin 5 low
GPIOA_ODR ^=  (1U << 5);     // toggle pin 5

Read the macro from the inside out: 0x40020014 is a number; (volatile uint32_t *) says "treat it as the address of a volatile 32-bit value"; the leading * says "the value at that address". The macro therefore behaves like a variable that is really hardware.

13.3 Grouping registers in a struct

A peripheral usually has many registers in a row. A struct that matches the layout lets you name them (this is what vendor headers like STM32 CMSIS do).

typedef struct {
    volatile uint32_t MODER;     // offset 0x00 : pin mode (input/output)
    volatile uint32_t OTYPER;    // offset 0x04
    volatile uint32_t OSPEEDR;   // offset 0x08
    volatile uint32_t PUPDR;     // offset 0x0C
    volatile uint32_t IDR;       // offset 0x10 : input data
    volatile uint32_t ODR;       // offset 0x14 : output data
} GPIO_TypeDef;
 
#define GPIOA ((GPIO_TypeDef *)0x40020000)
 
GPIOA->MODER |= (1U << (5 * 2));   // pin 5 as output (2 bits per pin)
GPIOA->ODR   ^= (1U << 5);          // toggle pin 5
if (GPIOA->IDR & (1U << 0)) { /* pin 0 is high */ }

13.4 Practice safely: simulate a register on a PC

You can test all the bit logic without hardware by pointing at a normal variable.

#include <stdio.h>
#include <stdint.h>
 
static volatile uint32_t fake_odr = 0;          // pretend hardware register
#define ODR (*(&fake_odr))
 
#define LED_PIN 5
 
int main(void) {
    ODR |= (1U << LED_PIN);                      // LED on
    printf("ODR = 0x%08X\n", (unsigned)ODR);
    ODR ^= (1U << LED_PIN);                      // toggle -> off
    printf("ODR = 0x%08X\n", (unsigned)ODR);
    return 0;
}

13.5 Read-modify-write and its risks

ODR |= mask looks like one operation, but the CPU does three: read the register, change the bits, write it back. If an interrupt changes the same register between the read and the write, its change is lost. Solutions: disable interrupts around it, or use hardware set and clear registers (BSRR on STM32, set/clear registers on ESP32 such as GPIO_OUT_W1TS and GPIO_OUT_W1TC) that change a bit with one write.

13.6 Function pointers and callbacks

A function pointer stores the address of a function. Embedded software uses them to let low-level drivers call back into your application code.

typedef void (*ButtonCallback)(void);
 
static ButtonCallback on_press = NULL;
 
void button_register(ButtonCallback cb) {      // driver API
    on_press = cb;
}
 
void button_isr(void) {                        // driver calls your code
    if (on_press != NULL) on_press();
}
 
void my_handler(void) { printf("Button pressed!\n"); }   // application code
 
int main(void) {
    button_register(my_handler);
    button_isr();                               // simulate an interrupt
    return 0;
}

Output:

Button pressed!

The driver does not need to know what your application does, and your application does not need to know how the button is read. This separation is the heart of clean driver design.

GPIO and Debouncing

In one line

GPIO (General Purpose Input/Output) pins let the microcontroller read buttons and drive LEDs; debouncing removes the false presses caused by a mechanical switch's contacts bouncing.

14.1 What is a GPIO pin?

A pin you can configure in software as an input (read high or low) or an output (drive high or low). High means close to the supply voltage (3.3 V on ESP32 and ESP8266, 5 V on Arduino Uno); low means 0 V.

ModeMeaning
InputPin listens. Reads 1 if voltage is high, 0 if low
Input with pull-upInternal resistor pulls the pin to high when nothing drives it
Input with pull-downInternal resistor pulls the pin to low when nothing drives it
Output push-pullPin actively drives both high and low (normal LED output)
Output open-drainPin can only pull low; a pull-up resistor makes high (I2C uses this)

14.2 Floating inputs and pull-up resistors

Analogy: a door that needs a spring

A door with no spring flaps open and shut in the wind. An input pin that is connected to nothing (floating) picks up noise and reads random 0s and 1s. A pull-up or pull-down resistor is the spring that holds the pin in a known state.

Common button wiring: connect the button between the pin and GND and enable the internal pull-up. Not pressed: pin reads HIGH. Pressed: pin reads LOW. This is called active-low and needs no external resistor.

ESP32 pin note

GPIO 34 to 39 on the ESP32 are input only and have no internal pull-up or pull-down. Use an external resistor there. Also avoid pins used for boot (such as GPIO 0, 2, 12 and 15) for buttons until you read the datasheet.

14.3 Output: driving an LED

const int LED_PIN = 2;
 
void setup() {
    pinMode(LED_PIN, OUTPUT);
}
 
void loop() {
    digitalWrite(LED_PIN, HIGH);
    delay(500);
    digitalWrite(LED_PIN, LOW);
    delay(500);
}

Always use a series resistor with an external LED. Example: supply 3.3 V, LED drop 2.0 V, wanted current 10 mA. R = (3.3 - 2.0) / 0.010 = 130 ohm. Use the next standard value, 150 or 220 ohm. Without a resistor the LED (or the pin) burns out.

  • Keep the current per pin small (a few mA up to about 10 mA is a safe habit). Check the datasheet limit.
  • For motors, relays and solenoids, never connect them directly to a pin. Use a transistor, MOSFET or driver module (L298, ULN2003) with a separate supply and a flyback diode.

const int BTN_PIN = 4;

}

14.5 Switch bounce

A mechanical button is two pieces of metal. When they touch, they vibrate and make and break contact many times for about 1 to 20 milliseconds before settling. The microcontroller is fast enough to see every one of these as a separate press.

What you doWhat the pin seesWhat your code may think
One pressHIGH, LOW, HIGH, LOW, HIGH, LOW (settles)3 presses
One releaseLOW, HIGH, LOW, HIGH (settles)2 releases

The result: a counter that jumps by 3 or a toggle that flips randomly. Debouncing makes one physical press produce exactly one event.

14.6 Software debouncing without blocking

The simple fix delay(20) after a press blocks the whole program. A better method: accept a new value only if it has stayed the same for a debounce time, using millis() for timing.

const int BTN_PIN = 4;
const unsigned long DEBOUNCE_MS = 30;
 
int stableState   = HIGH;      // debounced state of the button
int lastReading   = HIGH;      // raw reading from the previous loop
unsigned long lastChange = 0;  // when the raw reading last changed
int pressCount = 0;
 
void setup() {
    pinMode(BTN_PIN, INPUT_PULLUP);
    Serial.begin(115200);
}
 
void loop() {
    int reading = digitalRead(BTN_PIN);
 
    if (reading != lastReading) {          // raw value changed: restart timer
        lastChange = millis();
        lastReading = reading;
    }
 
    if ((millis() - lastChange) > DEBOUNCE_MS && reading != stableState) {
        stableState = reading;             // it stayed stable long enough
        if (stableState == LOW) {          // falling edge = real press
            pressCount++;
            Serial.println(pressCount);
        }
    }
}

The program stays free to do other work in loop() because nothing waits. The trick: millis() - lastChange measures how long the raw reading has stayed the same.

14.7 Edge detection: act on the change, not the level

  • Level: "the button IS pressed". If you toggle an LED while it is pressed, it flickers thousands of times per second.
  • Edge: "the button WAS JUST pressed". Compare the current stable state with the previous one and act once.
  • Falling edge = HIGH to LOW (press with pull-up). Rising edge = LOW to HIGH (release).

Interrupts and ISR

In one line

An interrupt makes the CPU pause its normal work, run a short function (ISR) to deal with an urgent event, and then continue exactly where it stopped.

15.1 Polling vs interrupts

Analogy: waiting for a visitor

Polling is walking to the door every few seconds to see if someone is there. An interrupt is a doorbell: you work normally, and when it rings you go to the door, then return to your work.

PollingInterrupt
Reaction timeDepends on how often you checkVery fast, hardware triggered
CPU useWastes time checkingUses CPU only when needed
ComplexitySimpleNeeds care (shared data, timing)
Good forSlow, non-urgent inputsUrgent events, short pulses, communication, wake from sleep

15.2 What happens when an interrupt fires

  1. A peripheral raises an interrupt request (button edge, timer overflow, byte received).
  2. If interrupts are enabled and the priority is high enough, the CPU finishes the current instruction.
  3. The CPU saves the context: program counter and key registers are pushed onto the stack.
  4. It looks up the address of the handler in the interrupt vector table and jumps to the ISR.
  5. The ISR runs and clears the interrupt flag if required.
  6. The CPU restores the saved context and continues the main program as if nothing happened.

The delay between the event and the first ISR instruction is the interrupt latency. Keeping ISRs short keeps latency for other interrupts low.

15.3 The golden rules of an ISR

RuleReason
Keep it short and fastWhile an ISR runs, other work and (often) other interrupts wait
No delay(), no waiting loopsThe timer that delay depends on may be blocked; the system freezes
No printf or Serial.printThey are slow, may use interrupts themselves and are not safe here
No malloc / freeNot re-entrant and unpredictable in time
Do not call functions that blockAnything that waits can hang the whole program
Share data through volatile variablesOtherwise the compiler may never see the change
Set a flag or push data to a buffer, process in mainWork in the ISR, think in main

15.4 Example: button interrupt with a flag

const int BTN_PIN = 4;
volatile bool buttonFlag = false;          // shared with the ISR: volatile
volatile unsigned long lastIsrTime = 0;
 
void IRAM_ATTR onButton() {                // ESP32: ISR must live in IRAM
    unsigned long now = millis();
    if (now - lastIsrTime > 50) {          // ignore bounces within 50 ms
        buttonFlag = true;                 // just set a flag
        lastIsrTime = now;
    }
}
 
void setup() {
    Serial.begin(115200);
    pinMode(BTN_PIN, INPUT_PULLUP);
    attachInterrupt(digitalPinToInterrupt(BTN_PIN), onButton, FALLING);
}
 
void loop() {
    if (buttonFlag) {                      // main code does the real work
        buttonFlag = false;
        Serial.println("Button pressed");
    }
    // other tasks keep running here
}
  • IRAM_ATTR is for ESP32 and ESP8266 (ICACHE_RAM_ATTR on older ESP8266 cores). It keeps the ISR in fast RAM so it can run while flash is busy. On an Arduino Uno you omit it.
  • FALLING, RISING, CHANGE choose which edge triggers the interrupt. LOW triggers repeatedly while the pin is low.
  • On an Uno only pins 2 and 3 support external interrupts. On ESP32 almost every GPIO does.

15.5 Race conditions and atomic access

A race condition happens when main code and an ISR use the same data and the result depends on timing.

Example of the problem

An 8-bit AVR reads a 16-bit variable in two steps. If an interrupt changes the variable between the two reads, main gets the low byte of the old value and the high byte of the new value: a number that never existed.

volatile uint16_t pulseCount = 0;      // incremented in an ISR
 
uint16_t readCount(void) {
    noInterrupts();                    // start critical section
    uint16_t copy = pulseCount;        // read safely
    interrupts();                      // end critical section
    return copy;
}

Keep critical sections as short as possible. On 32-bit chips a 32-bit read is a single instruction and is already atomic, but read-modify-write sequences like count++ still are not.

15.6 Priority, nesting and flags

  • Each interrupt source has a priority. A higher priority interrupt can pre-empt a lower one if nesting is enabled (ARM Cortex-M NVIC supports it).
  • Many peripherals have an interrupt flag that you must clear in the ISR; otherwise the ISR is called again immediately.
  • Global enable: noInterrupts() or interrupts() on Arduino; __disable_irq() and __enable_irq() on ARM.
  • Each source also has its own enable bit, so you can turn on only the interrupts you need.

15.7 Using the AVR timer interrupt (Uno)

volatile unsigned long ticks = 0;
 
ISR(TIMER2_COMPA_vect) {      // ISR macro from avr/interrupt.h
    ticks++;
}

Q1. What is an interrupt? A hardware signal that makes the CPU pause, run a handler and then resume.

TOPIC 16

Timers, PWM and ADC

In one line

A timer counts clock ticks to measure and create precise time; PWM uses fast on-off switching to control power; an ADC converts a real-world voltage into a number.

16.1 Timers

A hardware timer is a counter that increases by one on every tick of a clock, completely independent of your program. It can raise an interrupt on overflow or when it reaches a chosen compare value.

Analogy: a kitchen timer

You set the number of minutes, go on cooking, and it rings at the right time. A hardware timer keeps counting while the CPU does other jobs.

Key terms:

  • Clock: the source, for example 16 MHz on the Uno or 80 MHz APB clock on an ESP32.
  • Prescaler: divides the clock to make slower ticks. Timer clock = system clock / prescaler.
  • Overflow: the counter reaches its maximum (255 for 8-bit, 65535 for 16-bit) and wraps to 0.
  • Compare match: the counter equals a value you chose; used to create exact periods.

How to calculate a period, step by step (Uno: 16 MHz clock, want 1 ms):

  1. Choose prescaler 64: timer clock = 16,000,000 / 64 = 250,000 ticks per second.
  2. One tick lasts 1 / 250,000 = 4 microseconds.
  3. 1 ms = 1000 us needs 1000 / 4 = 250 ticks.
  4. The counter counts from 0, so set the compare value to 250 - 1 = 249.
// Arduino Uno: Timer2 generates an interrupt every 1 ms
volatile unsigned long ms = 0;
 
void setup() {
    noInterrupts();
    TCCR2A = (1 << WGM21);                  // CTC mode: clear counter on match
    TCCR2B = (1 << CS22);                   // prescaler 64
    OCR2A  = 249;                           // compare value
    TIMSK2 = (1 << OCIE2A);                 // enable compare-match interrupt
    interrupts();
}
 
ISR(TIMER2_COMPA_vect) {
    ms++;                                   // runs every 1 ms
}
 
void loop() {
    // use ms as a millisecond clock here
}

This register-level code is for the Uno (AVR). Using Timer2 leaves Timer0 free for millis() and delay(), but tone() also uses Timer2. On ESP32 and ESP8266 the timer API differs between core versions, so check the documentation of the core you installed. The calculation is the same on every chip.

16.2 Non-blocking timing with millis()

unsigned long previous = 0;
const unsigned long INTERVAL = 1000;     // 1 second
bool ledOn = false;
 
void loop() {
    unsigned long now = millis();
    if (now - previous >= INTERVAL) {    // subtraction is safe when millis() wraps
        previous = now;
        ledOn = !ledOn;
        digitalWrite(2, ledOn);
    }
    // loop keeps running: read sensors, check buttons...
}

16.3 PWM: Pulse Width Modulation

PWM switches a pin on and off very fast. The fraction of time it is ON is the duty cycle. A load that cannot follow such fast changes (an LED to the eye, a motor with inertia) sees the average.

Duty cycleAverage voltage (3.3 V)Effect
0%0 VAlways off
25%0.83 VDim LED, slow motor
50%1.65 VHalf brightness or speed
75%2.48 VBright
100%3.3 VAlways on
  • Duty cycle (%) = ON time / total period x 100.
  • Frequency = 1 / period. LED dimming works well above about 500 Hz (no visible flicker). Motors often use 1 to 20 kHz.
  • Resolution = number of steps. 8-bit PWM has 256 levels (0 to 255); 10-bit has 1024.
  • Arduino Uno: analogWrite(pin, 0 to 255) on PWM pins 3, 5, 6, 9, 10, 11 (marked with ~).
  • ESP32: the LEDC peripheral gives PWM on any output pin. The function names changed between Arduino-ESP32 core versions 2 and 3, so follow the documentation for your installed version.
// Arduino Uno: fade an LED on pin 9
int brightness = 0;
int step = 5;
 
void setup() { pinMode(9, OUTPUT); }
 
void loop() {
    analogWrite(9, brightness);            // 0 = off, 255 = full
    brightness += step;
    if (brightness <= 0 || brightness >= 255) step = -step;
    delay(20);
}

Servo motors use a specific PWM: 50 Hz (20 ms period) with a pulse of 1 ms (one end), 1.5 ms (centre) and 2 ms (other end). Use a Servo library so the timing is exact.

16.4 ADC: Analog to Digital Converter

The world is analog: temperature, light, sound and battery level are smoothly changing voltages. The CPU understands numbers. The ADC measures a voltage and returns a number.

BoardResolutionCount rangeInput range
Arduino Uno10 bit0 to 10230 to 5 V
ESP3212 bit0 to 4095about 0 to 3.3 V
ESP8266 (NodeMCU A0)10 bit0 to 10230 to 3.3 V (board divider)

Conversion formula (using the full-scale count):

voltage = count x Vref / maxCount

Example (Uno): count 512, Vref 5 V, max 1023: voltage = 512 x 5 / 1023 = 2.50 V.

Resolution (step size) = Vref / 2^N. A 10-bit ADC at 5 V has steps of about 4.9 mV; a 12-bit ADC at 3.3 V has steps of about 0.8 mV.

// Read an LM35 temperature sensor (10 mV per degree C) on an Uno
const int SENSOR = A0;
 
void setup() { Serial.begin(9600); }
 
void loop() {
    int count = analogRead(SENSOR);               // 0 to 1023
    float volts = count * 5.0f / 1023.0f;
    float tempC = volts * 100.0f;                 // 10 mV per degree
    Serial.println(tempC);
    delay(1000);
}

16.5 Getting clean ADC readings

  • Noise: average several samples (for example 16) or use a moving average.
  • Keep analog wires short, and add a 0.1 uF capacitor close to the sensor.
  • Reference voltage: the result is only as accurate as Vref. A battery-powered board can have a drifting 5 V or 3.3 V supply.
  • ESP32 notes: the ADC is not perfectly linear (use calibration functions), and ADC2 channels cannot be used while Wi-Fi is on. Prefer ADC1 pins (GPIO 32 to 39) in Wi-Fi projects.
  • Never apply more than the maximum input voltage (3.3 V on ESP boards) to an ADC pin. Use a voltage divider for higher voltages.
int readAveraged(int pin, int samples) {
    long sum = 0;
    for (int i = 0; i < samples; i++) {
        sum += analogRead(pin);
        delay(2);
    }
    return (int)(sum / samples);
}

TOPIC 17

Communication Protocols: UART, I2C and SPI

In one line

Protocols are agreed rules for sending bytes between chips: UART is a simple two-wire serial link, I2C connects many devices on two shared wires, and SPI is a fast four-wire link.

17.1 Serial vs parallel, sync vs async

  • Serial: bits are sent one after another on a single wire. Fewer wires, so it is used almost everywhere.
  • Asynchronous (UART): no shared clock wire; both sides agree on the speed (baud rate) in advance.
  • Synchronous (I2C, SPI): a clock wire tells the receiver exactly when to read each bit.

17.2 UART

UART (Universal Asynchronous Receiver Transmitter) connects exactly two devices. It is what the Serial Monitor, GPS modules, Bluetooth modules (HC-05) and many sensors use.

WireConnection
TXTransmit of device A goes to RX of device B
RXReceive of device A comes from TX of device B (so TX and RX are crossed)
GNDCommon ground is mandatory

Frame format 8N1 (the most common): when idle the line is HIGH. One byte is sent as: 1 start bit (LOW), 8 data bits (least significant bit first), no parity, 1 stop bit (HIGH). That is 10 bits for 8 bits of data.

  • Baud rate = bits per second. Common: 9600, 115200.
  • Time for one byte at 9600 baud = 10 / 9600 = about 1.04 ms. So 9600 baud moves roughly 960 bytes per second.
  • Both devices must use the same baud rate and format, otherwise you see garbage characters.
  • Voltage levels must match: do not connect 5 V TX to a 3.3 V RX without a level shifter or divider.
void setup() {
    Serial.begin(115200);                  // must match the Serial Monitor
}
 
void loop() {
    if (Serial.available() > 0) {          // a byte has arrived
        char c = Serial.read();
        Serial.print("Got: ");
        Serial.println(c);
    }
}

Receiving commands properly: build a line in a buffer until you see a newline, then parse it. Check buffer length so a long message cannot overflow it.

char line[32];
uint8_t len = 0;
 
void loop() {
    while (Serial.available() > 0) {
        char c = Serial.read();
        if (c == '\n') {
            line[len] = '\0';
            handle_command(line);          // e.g. compare with strcmp
            len = 0;
        } else if (len < sizeof(line) - 1) {
            line[len++] = c;               // protect against overflow
        }
    }
}

17.3 I2C

I2C (Inter-Integrated Circuit, "I squared C") uses just two shared wires for many devices: SDA (data) and SCL (clock). One master (your microcontroller) talks to several slaves (sensors, displays, EEPROM). Each slave has a 7-bit address.

Analogy: a classroom

The teacher (master) calls a student by name (the address) and asks a question. Only the student whose name was called answers. Everyone shares the same room (the two wires).

  • Both lines are open-drain, so each needs a pull-up resistor to the supply (typically 4.7 kohm; 2.2 to 10 kohm is the usual range). Many breakout boards already have them.
  • Speeds: 100 kHz standard, 400 kHz fast mode.
  • A transaction: START, 7-bit address plus read/write bit, ACK from the slave, data bytes each with an ACK, STOP.
  • Default pins: Uno SDA = A4, SCL = A5. ESP32 SDA = GPIO 21, SCL = GPIO 22. ESP8266 NodeMCU SDA = D2 (GPIO 4), SCL = D1 (GPIO 5).
  • Two devices with the same address cannot share a bus without a multiplexer or an address pin.
// I2C scanner: finds the addresses of all connected devices
#include <Wire.h>
 
void setup() {
    Serial.begin(115200);
    Wire.begin();
    for (uint8_t addr = 1; addr < 127; addr++) {
        Wire.beginTransmission(addr);
        if (Wire.endTransmission() == 0) {           // 0 = device answered (ACK)
            Serial.print("Found device at 0x");
            Serial.println(addr, HEX);
        }
    }
}
 
void loop() {}
// Read two bytes from a sensor register (generic pattern)
Wire.beginTransmission(0x48);       // device address
Wire.write(0x00);                   // register to read
Wire.endTransmission();
 
Wire.requestFrom(0x48, 2);          // ask for 2 bytes
if (Wire.available() >= 2) {
    uint8_t hi = Wire.read();
    uint8_t lo = Wire.read();
    int16_t raw = (hi << 8) | lo;   // combine: byte order from the datasheet
}

Typical I2C devices: OLED SSD1306 (0x3C), MPU6050 (0x68), BMP280 (0x76 or 0x77), RTC DS3231 (0x68), LCD backpack (0x27 or 0x3F). A common error: SDA and SCL swapped or missing pull-ups, so the scanner finds nothing.

17.4 SPI

SPI (Serial Peripheral Interface) is fast and simple: one master and one or more slaves. Data goes in both directions at the same time (full duplex).

WireMeaning
SCKClock from the master
MOSIMaster Out, Slave In: data from master to slave
MISOMaster In, Slave Out: data from slave to master
CS (SS)Chip Select, one per slave; pull LOW to talk to that slave
  • Speeds from 1 MHz to tens of MHz, much faster than I2C. Used for SD cards, displays (TFT), flash memory, ADCs and radio modules (NRF24, LoRa).
  • Every bit sent by the master shifts one bit in from the slave at the same time. To read, the master sends dummy bytes.
  • Four modes (0 to 3) set the clock idle level (CPOL) and which edge samples data (CPHA). Master and slave must use the same mode; check the datasheet.
  • Each extra slave needs one more CS pin, so SPI uses more wires than I2C.
#include <SPI.h>
 
const int CS_PIN = 5;
 
void setup() {
    pinMode(CS_PIN, OUTPUT);
    digitalWrite(CS_PIN, HIGH);          // idle: slave not selected
    SPI.begin();
}
 
uint8_t spiReadRegister(uint8_t reg) {
    SPI.beginTransaction(SPISettings(1000000, MSBFIRST, SPI_MODE0));
    digitalWrite(CS_PIN, LOW);           // select the slave
    SPI.transfer(reg | 0x80);            // send register address (read flag is device specific)
    uint8_t value = SPI.transfer(0x00);  // send dummy byte, get the answer
    digitalWrite(CS_PIN, HIGH);          // release the slave
    SPI.endTransaction();
    return value;
}

Quick rule: need to talk to a PC or a module with a serial port, use UART; many slow sensors on few pins, use I2C; high data rate, use SPI.

17.6 Multi-byte values and byte order

A 16-bit sensor value arrives as two bytes. The datasheet says which byte comes first. Combine as (high << 8) | low if the high byte arrives first. Mixing this up is a very common bug (see endianness in Topic 12).

Interview questions with short answers

Q1. What is baud rate? The number of symbols (bits) sent per second on a serial line.

Q2. What does 8N1 mean? 8 data bits, no parity, 1 stop bit.

Q3. Why does I2C need pull-up resistors? The lines are open-drain, so devices can only pull them low; resistors pull them high.

Q4. How many devices can an I2C bus have? Up to 112 usable 7-bit addresses in theory, fewer in practice because of capacitance and address clashes.

Q5. What are MOSI, MISO, SCK and CS? Master out slave in, master in slave out, clock, and chip select.

Q6. I2C vs SPI? I2C uses two wires and addresses but is slower; SPI is faster and full duplex but needs more pins.

Q7. Why is the ground connection important? Signals are voltages relative to ground; without a common ground the receiver has no reference.

TOPIC 18

Embedded Design Patterns: Buffers, State Machines, Watchdog, Sleep and RTOS

In one line

These are the reusable building blocks of real firmware: a ring buffer to pass data safely, a state machine to organise behaviour, a watchdog to recover from hangs, sleep modes to save power and an RTOS to run several tasks.

18.1 Circular (ring) buffer

A fixed-size buffer that wraps around. New data is written at the head; old data is read from the tail. Both indexes wrap to 0 when they reach the end. It is used for UART receive data, sensor samples and logging.

Analogy: a circular conveyor belt

One person puts items on the belt (head), another takes them off (tail). The belt never ends, it loops. If the putter is faster than the taker for too long, the belt fills up (overflow).

#include <stdint.h>
#include <stdbool.h>
 
#define BUF_SIZE 8                   // use a power of 2 so we can wrap with a mask
 
typedef struct {
    uint8_t data[BUF_SIZE];
    volatile uint8_t head;           // written by the producer (ISR)
    volatile uint8_t tail;           // written by the consumer (main)
} RingBuffer;
 
bool rb_is_empty(const RingBuffer *rb) { return rb->head == rb->tail; }
bool rb_is_full (const RingBuffer *rb) {
    return ((rb->head + 1) & (BUF_SIZE - 1)) == rb->tail;   // one slot stays empty
}
 
bool rb_put(RingBuffer *rb, uint8_t byte) {
    if (rb_is_full(rb)) return false;                    // overflow: report it
    rb->data[rb->head] = byte;
    rb->head = (rb->head + 1) & (BUF_SIZE - 1);          // wrap: same as % 8
    return true;
}
 
bool rb_get(RingBuffer *rb, uint8_t *byte) {
    if (rb_is_empty(rb)) return false;
    *byte = rb->data[rb->tail];
    rb->tail = (rb->tail + 1) & (BUF_SIZE - 1);
    return true;
}
  • Empty: head == tail. Full: advancing head would hit tail. Keeping one slot unused avoids confusing empty with full.
  • With one producer (ISR) and one consumer (main), each writes only its own index, so no lock is needed on a single-core chip as long as index updates are atomic (8-bit on AVR, 32-bit on ARM).
  • Size a power of two so the wrap is a fast AND mask instead of a slow divide.
  • Always decide what to do on overflow: drop new data, drop old data, or raise an error flag.

Typical use: the UART receive ISR calls rb_put for each byte; loop() calls rb_get and processes whatever has arrived.

18.2 Finite state machine (FSM)

Many devices behave differently depending on what they are doing: waiting, running, error. A state machine keeps a variable for the current state and decides what to do next from the state and the event. It replaces tangled if-else flags with clear, testable logic.

Current stateEventActionNext state
REDTimer (10 s)Turn red off, green onGREEN
GREENTimer (10 s)Turn green off, yellow onYELLOW
YELLOWTimer (3 s)Turn yellow off, red onRED
typedef enum { STATE_RED, STATE_GREEN, STATE_YELLOW } State;
 
State state = STATE_RED;
unsigned long stateStart = 0;
 
void setLights(bool r, bool y, bool g) {
    digitalWrite(RED_PIN, r);  digitalWrite(YELLOW_PIN, y);  digitalWrite(GREEN_PIN, g);
}
 
void loop() {
    unsigned long now = millis();
 
    switch (state) {
        case STATE_RED:
            setLights(1, 0, 0);
            if (now - stateStart >= 10000) { state = STATE_GREEN;  stateStart = now; }
            break;
        case STATE_GREEN:
            setLights(0, 0, 1);
            if (now - stateStart >= 10000) { state = STATE_YELLOW; stateStart = now; }
            break;
        case STATE_YELLOW:
            setLights(0, 1, 0);
            if (now - stateStart >= 3000)  { state = STATE_RED;    stateStart = now; }
            break;
    }
}
  • Draw the state diagram first (circles for states, arrows for events). Code follows the drawing.
  • The program never blocks: every pass of loop() checks the event and moves on, so it can serve other tasks too.
  • Add an ERROR state and make sure every state handles unexpected events.
  • Bigger machines use a table of function pointers, one per state (Topic 13).

You already built a traffic signal project; rebuilding it as an explicit state machine is a very good interview story.

18.3 Watchdog timer

A watchdog is a hardware timer that resets the chip if your software does not "kick" (reset) it within a set time. If the code hangs in an infinite loop or crashes, the watchdog restarts the device automatically.

Analogy: a dead-man's switch

A train driver must press a pedal every few seconds. If the driver stops pressing, the train brakes automatically. The watchdog is the pedal; the reset is the brake.

// Arduino Uno (AVR)
#include <avr/wdt.h>
 
void setup() {
    wdt_enable(WDTO_2S);        // reset if not kicked within 2 seconds
}
 
void loop() {
    do_work();
    wdt_reset();                // kick the watchdog: "I am still alive"
}
  • Kick the watchdog only when the whole system is healthy, at one place in the main loop. Kicking it from a timer ISR defeats its purpose, because the ISR keeps running even if main is stuck.
  • Choose a timeout longer than your slowest legitimate loop.
  • After a reset, check the reset reason and log it so you know the watchdog fired.
  • ESP32 has task watchdogs under FreeRTOS: a task that runs too long without yielding triggers a reset message. Add small delays or yield in long loops.
  • Safety-related products require a watchdog.

18.4 Low-power and sleep modes

Battery products spend most of their time asleep. A CPU running at full speed may draw tens of milliamps; deep sleep can be microamps.

ModeWhat happensWake-up sources
ActiveEverything runs-
Light / idle sleepCPU stops, peripherals and RAM stay on; quick wakeTimer, UART, GPIO interrupts
Deep sleepAlmost everything off; RAM often lost; slow wakeRTC timer, special pins, touch
// ESP32: sleep 10 seconds, wake, read the sensor, sleep again
void setup() {
    Serial.begin(115200);
    read_and_send_sensor();                       // do the work quickly
 
    esp_sleep_enable_timer_wakeup(10ULL * 1000000ULL);   // time in microseconds
    esp_deep_sleep_start();                       // the chip restarts at setup() on wake
}
 
void loop() {}                                    // never reached
  • Waking from deep sleep runs setup() again; variables in normal RAM are lost. Keep important values in RTC memory (RTC_DATA_ATTR) if needed.
  • The sleep strategy matters more than the sleep function: wake, measure, transmit, sleep. Turn off Wi-Fi and unused peripherals.
  • Average current = (active current x active time + sleep current x sleep time) / total time. Short active bursts give very long battery life.

18.5 Introduction to an RTOS

A Real-Time Operating System lets you write several independent tasks (read sensor, update display, handle Wi-Fi) that appear to run at the same time. A scheduler switches between them. The ESP32 Arduino core already runs on FreeRTOS, and your loop() is one task.

TermMeaning
TaskAn independent function with its own stack and priority
SchedulerDecides which task runs, usually the highest priority one that is ready
DelayvTaskDelay lets other tasks run while this one waits (unlike delay-busy waiting)
QueueThread-safe way to pass data between tasks or from an ISR to a task
Semaphore / MutexSignals an event or protects a shared resource from two tasks at once
// ESP32 (Arduino core): two tasks
void blinkTask(void *param) {
    pinMode(2, OUTPUT);
    while (true) {
        digitalWrite(2, !digitalRead(2));
        vTaskDelay(500 / portTICK_PERIOD_MS);       // sleep 500 ms, others run
    }
}
 
void sensorTask(void *param) {
    while (true) {
        int v = analogRead(34);
        Serial.println(v);
        vTaskDelay(1000 / portTICK_PERIOD_MS);
    }
}
 
void setup() {
    Serial.begin(115200);
    xTaskCreate(blinkTask,  "blink",  2048, NULL, 1, NULL);   // name, stack bytes, param, priority, handle
    xTaskCreate(sensorTask, "sensor", 4096, NULL, 1, NULL);
}
 
void loop() {}
  • Use an RTOS when you have several activities with different timing. Use a simple super-loop with a state machine when the program is small.
  • Shared data between tasks needs a mutex or a queue, otherwise you get race conditions just like with interrupts.
  • Each task needs enough stack; too little causes crashes (check with uxTaskGetStackHighWaterMark).

Interview questions with short answers

Q1. What is a circular buffer and where is it used? A fixed-size FIFO that wraps around; used for UART data, sensor streams and logs.

Q2. How do you tell a full buffer from an empty one? Empty when head equals tail; full when head + 1 equals tail (one slot kept free), or use a count variable.

Q3. What is a finite state machine? A model with a finite set of states and rules that move between them when events occur.

Q4. What is a watchdog timer? A hardware timer that resets the system if the software fails to reset it in time.

Q5. Why should you not kick the watchdog from an ISR? The ISR can keep running while main is stuck, hiding the hang.

Q6. What is the difference between light sleep and deep sleep? Light sleep stops the CPU but keeps RAM and quick wake; deep sleep powers down almost everything for the lowest current but restarts the program.

Q7. Super-loop vs RTOS? A super-loop is one endless loop (simple); an RTOS schedules several tasks with priorities and timing guarantees.

Q8. What is a mutex? A lock that lets only one task use a shared resource at a time.
